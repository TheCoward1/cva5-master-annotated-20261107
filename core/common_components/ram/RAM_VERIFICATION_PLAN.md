# RAM 模块验证计划

> 目录：`core/common_components/ram`

## 推荐验证顺序

| 顺序 | 模块 | 文件 | 优先级 | 主要验证内容 |
|---:|---|---|---|---|
| 1 | `lutram_1w_1r` | `lutram_1w_1r.sv` | 中 | 同步写、组合读、写使能、地址边界、读写同地址 |
| 2 | `lutram_1w_mr` | `lutram_1w_mr.sv` | 中高 | 多读端口、Xilinx/Intel 两个 generate 分支 |
| 3 | `sdp_ram` | `sdp_ram.sv` | 高 | 分列写使能、读使能、流水线深度、同址读写 |
| 4 | `sdp_ram_padded` | `sdp_ram_padded.sv` | 高 | 列填充后的数据映射、部分写、读回数据 |
| 5 | `tdp_ram` | `tdp_ram.sv` | 最高 | 双端口并发访问、同址冲突、预加载、流水线 |

## 各模块验证重点

### 1. `lutram_1w_1r`

- 写使能为 0 时不能写入。
- 写使能为 1 时，写入后能够正确读出。
- 读写不同地址时互不影响。
- 读写同一地址时，检查时钟沿后的读数据。
- 检查地址 `0` 和 `DEPTH-1` 边界。
- 使用全 0、全 1、交替模式、单 bit 和随机数据进行测试。
- 注意该模块是同步写、组合读，读延迟模型与 `sdp_ram` 不同。

### 2. `lutram_1w_mr`

- 检查多个读端口是否都能读到正确数据。
- 检查不同读端口读不同地址时是否互不干扰。
- 写入后检查所有读端口是否都能看到更新数据。
- 验证 `NUM_READ_PORTS=1、2、4` 等配置。
- 分别编译和验证 `FPGA_VENDOR == XILINX` 与 `FPGA_VENDOR == INTEL` 两个分支。
- Intel 分支由多个 `lutram_1w_1r` 组成，需要确认所有实例都能正确写入同一份数据。

### 3. `sdp_ram`

- 验证 `a_en=0` 时不写入。
- 验证 `a_wbe` 全 0、全 1、单 bit 置位和交替模式。
- 检查部分列写入后，未写列的数据是否保持不变。
- 验证 `b_en=0` 和 `b_en=1` 时读输出的行为。
- 验证 `PIPELINE_DEPTH=0、1、2` 时的读延迟。
- 进行连续读写、背靠背访问和地址边界测试。
- 检查 A 口写和 B 口读同一地址时的行为。
- 对不同的 `NUM_COL`、`COL_WIDTH` 参数进行配置测试。

### 4. `sdp_ram_padded`

- 验证 `NUM_COL=1` 时直接使用 `sdp_ram` 的分支。
- 验证有填充和无填充两种情况。
- 重点检查 `COL_WIDTH=8、12、16、17` 等不同填充情况。
- 检查每个逻辑列是否映射到正确的物理列。
- 写入后读回，检查原始位序是否保持不变。
- 检查部分写使能时是否只修改对应列。
- 不能只使用随机整体数据，必须使用能够区分各列的 bit pattern。

### 5. `tdp_ram`

- 验证 A、B 两端独立写不同地址。
- 验证 A、B 两端独立读不同地址。
- 验证一端写、另一端同时读。
- 验证两端同时写同一个地址。
- 验证两端同时写相同地址的不同列。
- 验证两端同时写相同地址的不同数据。
- 验证 `PIPELINE_DEPTH=0、1、2`。
- 验证 `USE_PRELOAD=1` 时的预加载文件。
- 明确并验证写操作期间读输出的语义。
- 明确并验证同址读写时读到旧数据还是新数据的语义。

## 建议的 testbench 结构

```text
RAM testbench
  ├── 时钟和复位
  ├── DUT 例化
  ├── 参考存储模型
  ├── 写操作驱动
  ├── 读操作驱动
  ├── scoreboard 比较
  └── 覆盖率和结果统计
```

参考模型可以使用关联数组：

```systemverilog
logic [DATA_WIDTH-1:0] ref_mem[logic [ADDR_WIDTH-1:0]];
```

写操作时同时更新参考模型，读操作时比较 DUT 输出和参考模型。

## 参数化测试建议

至少覆盖：

```text
ADDR_WIDTH      = 2, 4, 8
NUM_COL         = 1, 2, 4
COL_WIDTH       = 8, 12, 16
PIPELINE_DEPTH  = 0, 1, 2
FPGA_VENDOR     = XILINX, INTEL
```

## 完成标准

- [ ] 每个模块有独立的参数化 testbench。
- [ ] 有参考模型和自动 scoreboard。
- [ ] 日志中能够统计 PASS/FAIL 和检查次数。
- [ ] 对合法参数组合进行定向测试。
- [ ] 对地址边界、写使能、部分写、流水线和冲突场景进行覆盖。
- [ ] 至少编译验证 `lutram_1w_mr` 的两个厂商分支。
- [ ] 归档仿真日志和覆盖率结果。
